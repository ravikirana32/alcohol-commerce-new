# P500.2 Retail Checkout Integration Remediation

Version: `0.500.2-dev`  
Baseline: P500 integration remediation `0.500.1-dev`  
Scope: Stabilise existing retail checkout; no new business feature.

## Implemented

1. Added `retail_sales.request_fingerprint` through forward-only migration `211_p5002_retail_checkout_fingerprint.sql`.
2. Canonical SHA-256 fingerprints cover outlet, receipt number, product/quantity lines and tender method/amount/reference.
3. Reusing an idempotency key for a different semantic request returns HTTP 409.
4. Legacy sale rows with no fingerprint are reconstructed from their persisted sale lines and tenders on first replay, compared, then backfilled.
5. Retail amount calculation uses integer minor units and per-line tax rounding.
6. Stock deductions are tenant/outlet/product scoped and guarded against negative balances at update time.
7. Retail checkout writes an audit event and exposes a scoped sale-detail endpoint with lines, tenders and refunds.
8. POS UI preserves the exact pending request and idempotency key after a failed/uncertain network response; it offers retry rather than creating a new sale key.
