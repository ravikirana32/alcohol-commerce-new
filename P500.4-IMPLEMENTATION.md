# P500.4 — Retail split tender and receipt workflow

Version: `0.500.4-dev`  
Status: developer preview; not production approved.

## Implemented
- Added multiple tender rows supporting cash, UPI, card, wallet and other payment types.
- Validates that the sum of tenders equals the server-calculated cart total before submission.
- Submits all positive tender allocations to the atomic retail/bar checkout API.
- Added receipt preview with item/tender breakdown and browser print stylesheet.
- Keeps exact request and idempotency key on uncertain checkout retry.

## Verification
- Retail integration checks: 12/12 passed.
- TypeScript/TSX syntax transpilation: 209 files, zero syntax diagnostics.

## Limitations
- Receipt preview is a browser-rendered print layout, not certified fiscal printer output.
- Split tender refund allocation, hardware printing and browser E2E remain outstanding.
- PostgreSQL/API runtime tests and full typecheck/build not run.
