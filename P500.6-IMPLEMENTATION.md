# P500.6 — Retail sales history and refund workflow

Version: `0.500.6-dev`  
Status: developer preview; not production approved.

## Implemented
- Added Sales & Refunds navigation and a retail sales history screen.
- Loads outlet-scoped recent sales and fetches tenant-scoped sale details.
- Displays sale totals, tender allocations and refund history.
- Adds refund form with amount, reason, method, reference and explicit restock choice.
- Displays remaining refundable amount and refreshes sale history after a successful refund.
- API enforces refund permission, locks the sale row, prevents refunds beyond remaining sale value and writes an audit event.

## Verification
- Retail sales/refund static checks: 9/9 passed.
- Shift integration checks: 9/9 passed.
- Retail checkout integration checks: 12/12 passed.
- TypeScript/TSX syntax transpilation: 211 files, zero diagnostics.

## Limitations
- Refund restocking is currently proportional to refund value across original sale lines; SKU-level return allocation and partial quantity selection are not implemented.
- No live API/DB/browser tests, refund provider settlement verification or independent audit.
- Refund access is role/permission gated at API; pilot roles must be configured and tested.
